# 日本麻将(立直麻将)规则范围

这份文档定的是 `riichi/` 引擎 **第一版做什么、不做什么**。基准是天凤段位战「四人打・喰断有・赤有・半庄」,因为以后要用天凤牌谱和现成工具做对照。有分歧的地方做成配置项(`riichi/config.py` 的 `RuleConfig`),下面标了默认值。

状态:**Adam 已确认(2026-11-22),引擎 `riichi/` 已按此实现**。标 ⚠ 的是按通行理解写的、还没有拿天凤牌谱逐条核对的细节。

## 0. 一眼看完

| 项 | 这一版 |
|---|---|
| 人数、局数 | 四人,半庄(东风战可配置),有西入 |
| 起始点 / 返点 | 25000 / 30000 |
| 赤宝牌 | 5万、5筒、5条各 1 张 |
| 喰断、后付 | 有 |
| 一发、里宝、杠宝、杠里 | 有 |
| 双响 | 有(供托和本场归头跳者);三响 = 流局 |
| 途中流局 | 九种九牌、四风连打、四杠散了、四家立直、三家和,全做 |
| 流局满贯 | 有 |
| 包牌 | 大三元、大四喜 |
| 数役满 | 有(13 番以上) |
| 切上满贯、双倍役满、人和、古役 | 不做 |
| 击飞 | 有(低于 0 分结束) |

## 1. 牌与座位

| 项 | 规定 |
|---|---|
| 牌 | 万、筒、条各 1–9,东南西北白发中,34 种 × 4 = 136 张 |
| 赤牌 | 5万、5筒、5条各有 1 张是赤的(配置 `aka`,默认开)。赤牌和普通 5 是同一种牌,只是多算 1 番宝牌 |
| 牌的编号 | 种类 0–33:万 0–8、筒 9–17、条 18–26、东南西北 27–30、白发中 31–33。具体一张牌再多三个编号:34 赤5万、35 赤5筒、36 赤5条 |
| 文本写法 | `"123m406p77s1122z"`:`0` 表示赤 5,`z` 是字牌(1–7 = 东南西北白发中) |
| 座位 | 0–3,固定不动;座位 0 是起家(第一局的庄家)。行牌顺序 0 → 1 → 2 → 3 |
| 自风 | 按离庄家的距离:庄家东,下家南,对家西,上家北 |
| 王牌 | 14 张:岭上牌 4 张,宝牌指示牌 5 张,里宝指示牌 5 张 |
| 可摸的牌 | 136 − 52(配牌)− 14(王牌)= 70 张;每开一次杠,可摸的牌少 1 张(海底牌前移) |

## 2. 一场(半庄)的流程

一个 `Game` 是 **一整场半庄**,不是一局。训练要看名次,名次只有打完一场才有。

| 项 | 规定 |
|---|---|
| 场风与局 | 东 1 局 → 东 4 局 → 南 1 局 → 南 4 局。配置 `length`:`"hanchan"`(默认)、`"tonpu"`(东风战),或 `"one"`(只打一局,测试用) |
| 连庄 | 庄家和牌;或荒牌流局时庄家听牌;或途中流局 |
| 轮庄 | 闲家和牌(庄家没和);或荒牌流局时庄家没听 |
| 本场 | 庄家和牌、任何流局都加 1;闲家和牌(庄家没和)清零。每本场:荣和多收 300,自摸每家多付 100 |
| 供托 | 立直棒留在桌上,下一个和牌的人拿走;双响时归头跳者(从放铳者起按行牌顺序最近的那位) |
| 结束:击飞 | 一局结束时有人低于 0 分,整场结束(刚好 0 分继续)。配置 `tobi`,默认开 |
| 结束:正常 | 南 4 局(东风战是东 4 局)结束且庄家不连庄,此时有人 ≥ 30000 就结束 |
| 结束:庄家止和 | 最后一局庄家连庄(和牌或听牌)时,如果庄家是第一名且 ≥ 30000,就结束 |
| 西入 | 最后一局结束没人到 30000:进下一个场风(半庄进西场,东风战进南场)继续。延长战里任何一局结束后有人 ≥ 30000 就立刻结束;延长的场风打完也结束 |
| 剩下的供托 | 整场结束时还在桌上的立直棒归第一名 |
| 同分 | 名次按离起家近的优先(座位号小的在前) |

## 3. 一局的流程

| 步骤 | 规定 |
|---|---|
| 配牌 | 每人 13 张,庄家再摸 1 张先出牌 |
| 宝牌 | 开局翻 1 张指示牌;宝牌是指示牌的下一张(9 → 1;东 → 南 → 西 → 北 → 东;白 → 发 → 中 → 白) |
| 行牌 | 摸牌 → (和 / 杠 / 立直 / 九种九牌)→ 出牌 → 其他人响应 |
| 结束 | 有人和牌;荒牌流局(可摸的牌摸完,最后一张弃牌没人和);途中流局 |

### 3.1 吃、碰、杠

| 规则 | 规定 |
|---|---|
| 吃 | 只能吃上家打出的牌,手里出两张组成顺子。三种形状:被吃的牌在顺子里最小、中间、最大 |
| 碰 | 任何一家打出的牌,手里有 2 张 |
| 大明杠 | 任何一家打出的牌,手里有 3 张 |
| 暗杠 | 自己摸牌后的回合,手里有 4 张。不破门清 |
| 加杠 | 自己摸牌后的回合,已经碰过,手里有第 4 张。吃碰之后的那一次出牌前不能杠 |
| 赤牌的选择 | 吃、碰时如果手里既有赤 5 又有普通 5,可以选用哪一张(动作编号里分开,见第 8 节) |
| 响应优先级 | 荣和 > 碰、大明杠 > 吃 |
| 喰替(食い替え) | 不允许。吃碰之后那一手不能打出和被吃碰的牌同种的牌(現物);吃了两面搭子时也不能打顺子另一头的那种牌(筋,例如用 56 吃 4,不能打 4 和 7)。如果这样一来没牌可打,这个吃碰就不合法 |
| 杠的次数 | 全场合计最多 4 次。可摸的牌剩 0 张时不能杠 |
| 岭上牌 | 杠成立后从王牌补 1 张,用它自摸是岭上开花 |
| 杠宝牌 | 暗杠:立刻翻。大明杠、加杠:这次出牌之后翻;出牌前又开了一次杠的,在再次开杠时翻 ⚠。岭上自摸时还没翻出来的不算 ⚠ |
| 抢杠 | 别人加杠的那张牌可以荣和,杠不成立。暗杠只有国士无双可以抢 |
| 最后一张 | 海底牌(最后一张可摸的牌)摸到后不能杠;河底牌(最后一张弃牌)只能荣和,不能吃碰杠 |
| 大明杠岭上开花的责任支付 | 不做(天凤没有),按普通自摸三家付 |

### 3.2 立直

| 规则 | 规定 |
|---|---|
| 条件 | 门清(暗杠不算破)、打出一张后听牌、点数 ≥ 1000、可摸的牌 ≥ 4 张 |
| 过程 | 宣言 → 打出一张。这张牌没被荣和,立直才成立,交 1000 点供托。被荣和则立直不成立,不交 |
| 立直之后 | 只能摸切。可以和,也可以不和(不和就永久振听) |
| 立直后的暗杠 | 只能杠刚摸到的那张(手里已有 3 张),并且杠后听的牌不变、不改变牌型的拆法(送杠不允许) |
| 一发 | 立直成立后,到自己下一次出牌之前和牌(含下一次摸牌自摸)。中间有任何人吃、碰、杠就没了 |
| 双立直 | 自己的第一次出牌就立直,且之前全场没有吃碰杠 |
| 里宝牌 | 立直者和牌时,每张已翻开的宝牌指示牌下面那张也算指示牌 |

### 3.3 和牌

| 规则 | 规定 |
|---|---|
| 和牌型 | 4 组面子 + 1 对雀头;七对子(7 个不同的对子,4 张相同的不能当两对);国士无双 |
| 至少一番 | 必须有役才能和。宝牌、赤宝、里宝不是役 |
| 自摸 | 自己摸到(含岭上牌) |
| 荣和 | 别人打出的牌,或抢杠 |
| 双响 | 两家同时荣和都成立,放铳者分别付。供托和本场只给头跳者 |
| 三响 | 算途中流局(三家和),没人得分 |
| 多种拆法 | 取点数最高的那种 |

### 3.4 振听

| 种类 | 规定 |
|---|---|
| 舍张振听 | 自己听的牌里有任何一种在自己的弃牌里(被别人吃碰走的也算)→ 不能荣和,可以自摸 |
| 同巡振听 | 别人打出(或加杠)了自己听的牌而没和(包括因为没役不能和)→ 到自己下一次出牌之前不能荣和 |
| 立直振听 | 立直后漏过一次自己听的牌 → 这一局都不能荣和 |

### 3.5 流局

| 种类 | 条件 | 结果 |
|---|---|---|
| 荒牌流局 | 可摸的牌摸完,最后一张弃牌没人和 | 听牌的和没听的之间付罚符,合计 3000:1 人听收 3000(每家 1000),2 人听各收 1500,3 人听各收 1000;全听或全没听不付 |
| 流局满贯 | 荒牌流局时,某家的弃牌全是幺九牌和字牌,且没有一张被别人吃碰杠走。配置 `nagashi_mangan`,默认开 | 按自摸满贯收分(闲家 8000,庄家 12000),不再算罚符;不拿供托,不加本场分;可以多家同时成立 |
| 九种九牌 | 第一巡、之前全场无吃碰杠,自己摸牌后手里有 9 种以上幺九牌和字牌,可以选择流局 | 途中流局 |
| 四风连打 | 第一巡四家打出同一种风牌,期间无吃碰杠 | 途中流局 |
| 四杠散了 | 两家以上合计开了 4 次杠,第 4 次杠之后的那张弃牌没人和。一家独开 4 杠不流局,但之后谁都不能再杠 | 途中流局 |
| 四家立直 | 第四家立直的那张弃牌没人和 | 途中流局(第四根立直棒照交) |
| 三家和 | 三家同时荣和 | 途中流局(这张牌如果是立直宣言牌,立直不成立) ⚠ |

| 流局后 | 规定 |
|---|---|
| 听牌的判断 | 再来一张就成和牌型(不要求有役)。只听自己手牌加副露里已经占满 4 张的牌,不算听牌 |
| 荒牌流局 | 庄家听牌连庄,否则轮庄;本场 +1 |
| 途中流局 | 一律连庄,本场 +1;没有罚符。配置 `abortive_draws`,默认开;关掉后这五种都不触发(三响时三家都和) |

## 5. 算分

### 5.1 符

| 项 | 符 |
|---|---|
| 底符 | 20 |
| 门清荣和 | +10 |
| 自摸 | +2(平和自摸不加,固定 20 符) |
| 明刻 | 中张 2,幺九字牌 4 |
| 暗刻 | 中张 4,幺九字牌 8 |
| 明杠 | 中张 8,幺九字牌 16 |
| 暗杠 | 中张 16,幺九字牌 32 |
| 雀头 | 三元牌、自风、场风各 +2;连风牌 +4 |
| 听牌形 | 嵌张、边张、单骑 +2;两面、双碰 0 |
| 副露的平和形 | 副露手牌算下来只有 20 符时,荣和按 30 符 |
| 进位 | 向上取到整十 |
| 七对子 | 固定 25 符,不进位 |

### 5.2 点数

基本点 = 符 × 2^(番 + 2),封顶如下。

| 档 | 条件 | 基本点 |
|---|---|---|
| 满贯 | 5 番;或 4 番 40 符以上、3 番 70 符以上(基本点超过 2000) | 2000 |
| 跳满 | 6–7 番 | 3000 |
| 倍满 | 8–10 番 | 4000 |
| 三倍满 | 11–12 番 | 6000 |
| 数役满 | 13 番以上 | 8000 |
| 役满 | 每一倍 | 8000 |
| 切上满贯(4 番 30 符、3 番 60 符算满贯) | ❌ 不做 | — |

| 和法 | 支付(每一笔向上取到整百) |
|---|---|
| 闲家荣和 | 放铳者付 基本点 × 4 |
| 庄家荣和 | 放铳者付 基本点 × 6 |
| 闲家自摸 | 庄家付 基本点 × 2,另两家各付 基本点 × 1 |
| 庄家自摸 | 三家各付 基本点 × 2 |
| 本场 | 荣和 +300 × 本场数;自摸每家 +100 × 本场数 |

### 5.3 包牌(配置 `pao`,默认开)

| 项 | 规定 |
|---|---|
| 对象 | 大三元:让对方碰或大明杠到第三种三元牌的人。大四喜:让对方碰或大明杠到第四种风牌的人 |
| 自摸 | 包牌者一人付全部 |
| 别人放铳 | 包牌者和放铳者各付一半;本场分由放铳者付 |
| 役满复合 | 只有包牌的那个役满按上面算,其余部分照常 |
| 四杠子的包牌 | ❌ 不做 |

### 5.4 名次分

| 项 | 规定 |
|---|---|
| 公式 | (终局点数 − 30000)÷ 1000 + 顺位马;第一名再加 20(四家起始点和返点的差) |
| 顺位马 | 一位 +20、二位 +10、三位 −10、四位 −20。配置 `uma` |
| 性质 | 四家名次分之和恒为 0 |
| 用处 | 引擎的 `scores` 是点数;`result()` 另给名次和名次分。训练用哪一个到训练阶段再定 |

## 6. 明确不做的

| 规则 | 说明 |
|---|---|
| 三人麻将 | 只做四人 |
| 人和、古役、地方役 | 见第 4 节 |
| 双倍役满 | 都按一倍 |
| 切上满贯 | — |
| 大明杠岭上开花的责任支付、四杠子包牌 | — |
| 完全先付、喰断无 | 喰断可以用 `kuitan` 关掉;先付规则不做 |
| 掷骰子、开门位置 | 牌墙直接由种子洗好 |
| 错和、多牌少牌等罚则 | 引擎只接受合法动作,不会出现 |
| 思考时间、超时 | 由上层(服务端)管 |
| 手切和摸切的区分作为动作 | 动作里不分;事件和视图里会标出每张弃牌是不是摸切 |
| 天凤的段位点数 | 只做顺位马的名次分 |

## 7. 引擎接口(照 `chuanma/` 的设计)

| 成员 | 含义 |
|---|---|
| `Game(config, seed, walls, record_events)` | 一场半庄。`seed` 决定每一局的洗牌;`walls` 可以指定每一局的 136 张牌墙(测试、复盘用) |
| `game.current` | 轮到哪个座位;结束后为 −1 |
| `game.legal_actions()` / `legal_action_ids()` | 当前决策者的合法动作 |
| `game.step(action)` | 执行一个动作;非法动作抛 `IllegalAction`,状态不变 |
| `game.observation(seat)` | 这个座位按规则能看到的东西(看不到别人的手牌、牌墙、里宝) |
| `game.is_over`、`game.scores` | 是否结束;四家点数。任何时刻 四家点数之和 + 1000 × 供托 = 100000 |
| `game.events` / `events_for(seat)` | 事件流 |
| `game.hand_results` | 每一局的结算(和牌者、役、符番、每一笔点数) |
| `game.result()` | 终局:点数、名次、名次分 |
| `GameRecord` / `replay` | 牌谱 = 配置 + 种子(或牌墙)+ 动作序列;重放到底时核对点数 |

| 阶段 `Phase` | 谁在决定 | 可选动作 |
|---|---|---|
| `TURN` | 轮到的人(摸牌后或吃碰后) | 出牌、立直、自摸、暗杠、加杠、九种九牌 |
| `RIICHI` | 刚宣言立直的人 | 出牌(只能选打出后仍听牌的) |
| `RESPONSE` | 能对弃牌做点什么的人,从放铳者下家起逐个问 | 荣和、碰、大明杠、吃、过 |
| `ROB_KAN` | 能抢杠的人,逐个问 | 荣和、过 |
| `END` | 无 | 无 |

`RESPONSE` 只问确实有事可做的人。全部答完后统一裁决:有人荣和则荣和成立(三家则流局),否则碰或杠,否则吃,否则下家摸牌。一局结束后引擎自动开下一局。

**牌墙的排法**(只和自定义牌墙有关):`wall[0:52]` 是配牌,座位 0–3 每人连续 13 张;从 `wall[52]` 起依次被摸走;最后 14 张是王牌:`wall[135]`、`[134]`、`[133]`、`[132]` 依次是第 1–4 张岭上牌;`wall[130]`、`[128]`、`[126]`、`[124]`、`[122]` 是第 1–5 张宝牌指示牌,各自下标加 1 的那张是对应的里宝指示牌。

## 8. 动作编号

固定不变,共 119 个(`NUM_ACTIONS`),神经网络的输出层和牌谱都用它。

| 编号 | 动作 | 参数 |
|---|---|---|
| 0–36 | `DISCARD` 出牌 | 牌(0–33 普通,34–36 赤 5) |
| 37–70 | `ANKAN` 暗杠 | 牌的种类 |
| 71–104 | `KAKAN` 加杠 | 牌的种类 |
| 105 | `RIICHI` 宣言立直 | —(下一步再选打哪张) |
| 106 / 107 | `CHI` 被吃的牌最小(例如吃 3,出 45) | 不用赤 5 / 用赤 5 |
| 108 / 109 | `CHI` 被吃的牌在中间(吃 4,出 35) | 不用赤 5 / 用赤 5 |
| 110 / 111 | `CHI` 被吃的牌最大(吃 5,出 34) | 不用赤 5 / 用赤 5 |
| 112 / 113 | `PON` 碰 | 不用赤 5 / 用赤 5 |
| 114 | `DAIMINKAN` 大明杠 | — |
| 115 | `TSUMO` 自摸 | — |
| 116 | `RON` 荣和(含抢杠) | — |
| 117 | `KYUUSHU` 九种九牌 | — |
| 118 | `PASS` 过 | — |

"用赤 5"指从手里拿出去的那两张里有赤 5。手里只有赤 5 没有普通 5 时,只有"用赤 5"那个编号合法。加杠和暗杠不用选:四张全都进副露。

## 9. 正确性怎么保证

| 手段 | 内容 |
|---|---|
| 规则用例 | 上面每一条做了的规则、每一个役、符和点数表,各有对应的测试 |
| 随机对局不变量 | 每种牌恒为 4 张、点数守恒、手牌张数正确、合法动作非空、同种子可复现、牌谱可重放 |
| 独立来源对照 | 用 PyPI 上的 `mahjong`(日麻算分库)对随机对局里出现的每一次和牌核对番、符、点数。这个库要另装,没装时这组测试自动跳过 |

## 10. 实现

| 模块 | 职责 |
|---|---|
| `riichi/tiles.py` | 牌的编号(34 种 + 3 张赤牌)、紧凑写法 `"123m406p11z"`、宝牌指示 |
| `riichi/config.py` | `RuleConfig`,上面所有的规则开关 |
| `riichi/actions.py` | `Action` 和 0..118 的固定编号 |
| `riichi/hand.py` | 和牌型(标准、七对子、国士)、听哪些牌、列出全部拆法 |
| `riichi/shanten.py` | 向听数、有效进张;`discard_shanten` 一次算出 14 张牌打每一张之后的向听(只重算改动的那一门) |
| `riichi/scoring.py` | 全部役、符、番、点数;同一手牌有多种拆法时取点数最高的,同点数优先役满 |
| `riichi/game.py` | `Game` 状态机:一整场半庄,含流程、合法动作、振听、流局、包牌、结算、视图、事件 |
| `riichi/record.py` | 牌谱 `GameRecord` 与 `replay`(重放到底时核对点数) |
| `riichi/agents.py` | `RandomAgent`、`SimpleAgent`、`ShantenAgent`(向听 + 进张,见下) |
| `riichi/runner.py`、`__main__.py` | 批量对局统计;命令行 `python -m riichi play` / `simulate` |
| `riichi/invariants.py` | 不变量检查(测试和长跑共用) |
| `tools/riichi_soak.py` | 多进程长跑验收 |

**规则型策略 `ShantenAgent`**(以后做模仿学习的老师和强度标尺):

| 场合 | 做法 |
|---|---|
| 出牌 | 向听数最小;同向听时有效进张(扣掉看得见的牌)最多;再比牌的价值,宝牌和赤牌尽量留 |
| 和牌 | 能和就和 |
| 立直 | 门清听牌就立直 |
| 吃碰 | 只碰役牌;已经副露了才吃碰能减少向听的牌 |
| 杠 | 暗杠、加杠在不增加向听时就杠;大明杠不杠 |
| 防守 | 别人立直而自己两向听以上:打现物,没有现物打字牌和幺九 |
| 九种九牌 | 幺九不到 11 种就流局 |

**长跑**(`tools/riichi_soak.py`,10 进程,每一步都查不变量):

| 策略 | 半庄 | 局 | 出错 | 用时 |
|---|---|---|---|---|
| 随机 | 10000 | 119383 | 0 | 144 秒 |
| 规则型 | 10000 | 100185 | 0 | 373 秒 |

规则型那 10000 场里:和了 89612 次(荣和 63216、自摸 26396),双响 1163 次,役满 11 次;途中流局 九种九牌 1200、四家立直 939、四风连打 412、三家和 6;击飞结束 3451 场。击飞偏多是因为这个策略防守弱(听牌就立直、两向听以内不弃和),不是引擎的问题。

**速度**(单核,Ryzen 7 9800X3D,不查不变量,每一步都构造视图字典):

| 策略 | 半庄/秒 | 局/秒 | 决策/秒 |

规则型慢在策略本身(每步要算几十次向听和进张),引擎本身的速度看随机策略那一行。训练时可以多进程并行,也可以像川麻那样跳过视图字典直接编码。

**和独立算分来源对照**:PyPI 的 `mahjong` 2.2.0(装在仓库里的 `.venv-riichi` 虚拟环境,不动全局环境),配置为 赤有、喰断有、没有双倍役满、数役满封顶一倍、不切上满贯、副露平和形荣和 30 符。

## 12. 对局软件

和川麻共用一个本地服务(`python -m server`),页面和连接各自独立。开始页点"日本麻将",或者直接打开 `http://127.0.0.1:8000/#riichi`。

| 部分 | 文件 | 内容 |
|---|---|---|
| 一场牌局 | `server/riichi_match.py` | `RiichiMatch`:1 人 + 3 个电脑(规则型或简单)打一整场半庄。每局结束时暂停,等人看完结算点"下一局"。视图里另加 `legal`(吃碰带 `uses`:从手里拿出去的两张)、`insight`(向听、进张)、`result`(暂停时)、`final`(终局) |
| 连接 | `server/riichi_ws.py` | `/ws/riichi`:`new_match`、`action`、`continue`、`quit_match`;`GET /api/riichi/opponents`。牌谱存到 `records/riichi/`,不混进川麻的牌谱列表 |
| 界面 | `frontend/src/riichi/` | 开始页、牌桌(宝牌指示牌、本场、供托、自风、立直棒、横放的宣言牌、被吃碰走的牌变淡)、出牌和吃碰杠立直按钮、牌理提示、每局结算(役和番符、宝牌和里宝)、终局名次和名次分。沿用琥珀夜色的设计变量和川麻牌桌的样式 |
| 赤五图片 | `tools/make_red_fives.py` | 把 5 万、5 筒、5 条的彩色笔画改成红色,生成 `man0/pin0/sou0.png` |

| 牌谱和观战 | `server/riichi_records.py`、`frontend/src/riichi/RiichiReplay.tsx` | 牌谱列表、逐步回放(四家明牌、可以跳到第几局)、四个电脑对打的观战 |
| 声音 | `frontend/src/sound.ts` 的 `playRiichiEvent` | 出牌、吃碰杠、立直、和牌的音效;四个音色报牌(字牌和"吃、立直、荣和"由 `tools/make_voice.py --missing` 生成) |
| 模型 | `riichi_ai/`,见 [riichi-training.md](riichi-training.md) | 神经网络对手、打牌提示、点炮概率、复盘分析 |
