# 日麻 AI 训练

路线和川麻一样([ai-training.md](ai-training.md)):规则型策略打底 → 模仿学习 → 自我对弈强化学习 → 导出 ONNX 入座。代码在 `riichi_ai/`,和川麻的 `ai/` 互不依赖。没有用天凤牌谱,也没有用外部的日麻环境,全部用本项目自己的引擎 `riichi/` 和训练代码。外部 AI Mortal 只用来当对照和下一步的老师,见 [riichi-mortal.md](riichi-mortal.md)。

## 1. 和川麻不一样的地方

| 项 | 川麻 | 日麻 |
|---|---|---|
| 一条轨迹 | 一个座位的一局(约 50 个决定) | 一个座位的一整场半庄(约 130 个有选择的决定) |
| 回报 | 本局得分 | 名次分:每次决定之间点数的变化 / 1000,终局再加名次马和返点差。一条轨迹的回报之和 = 终局名次分 − 第一次决定时的 (点数 − 25000)/1000 |
| 价值头的单位 | 分 / 8 | 名次分 / 20 |
| 输入 | 71 × 27 | 80 × 34(多了宝牌、立直、点数、场况、役牌等) |
| 动作 | 115 个 | 119 个(吃的三种形状 × 是否用赤 5、立直、九种九牌等) |
| 额外的头 | — | 点炮头:34 种牌各自"现在打出去会被荣和"的概率 |
| 评估指标 | 平均每局得分 | 平均名次分(每场),另报平均顺位、和了率、放铳率 |

## 2. 状态编码(`riichi_ai/encoding.py`)

80 个通道 × 34 种牌,只用这个座位能看到的信息,座位一律用相对位置。

| 通道组 | 通道数 | 内容 |
|---|---|---|
| 手牌 | 4 | 第 k 个通道表示这种牌至少有 k 张 |
| 赤 5、刚摸的牌 | 2 | — |
| 四家的副露 | 16 | 每家 4 个通道 |
| 四家的弃牌 | 16 | 每家 4 个通道(含被吃碰走的) |
| 立直宣言牌、最近打出的一张 | 8 | 每家各 1 个通道 |
| 宝牌 | 1 | 这种牌是几重宝牌 |
| 没见过的张数 | 4 | — |
| 等我响应的牌、喰替禁打的牌、役牌 | 3 | — |
| 阶段、四家立直、庄家位置、四家点数 | 16 | 标量,整个通道填同一个数 |
| 第几局、本场、供托、余牌、振听 | 5 | 标量 |
| 响应的牌来自谁、是不是加杠/暗杠 | 5 | 标量 |

| 入口 | 用在哪 |
|---|---|
| `encode(game, seat)` | 训练,直接读引擎状态,约 70 微秒 |
| `encode_obs(obs)` | 对局软件,只用 `observation()` 的字典 |
| `encode_oracle(game, seat)` | 看全场的价值头:三家手牌、牌墙、里宝 |
| `danger_labels(game, seat)` | 点炮头的标签:看全场算出打出每种牌是否有人能荣和(听这张、不振听、有役) |

前两个在每个决策点、四个座位的视角下完全一样(`tests/test_riichi_encoding.py`),这同时证明训练用的编码没有偷看。

## 3. 网络(`riichi_ai/model.py`)

| 项 | 设计 |
|---|---|
| 主干 | 一维残差卷积,沿 34 个牌位;10 个残差块 × 128 通道,225 万参数 |
| 策略头 | 119 个 logit,非法动作置为负无穷 |
| 价值头 | 预计这一场还会得多少名次分 |
| 点炮头 | 每个牌位一个 logit(局部特征 + 全局特征),二元交叉熵;只在"自己回合、刚摸完牌"的样本上训练 |
| 看全场的价值头 | 另一路输入三家手牌和牌墙,只接到这个头上,上线不导出 |

## 4. 模仿学习

| 项 | 内容 |
|---|---|
| 老师 | 规则型策略 `ShantenAgent`(见 [riichi-rules.md](riichi-rules.md) 第 10 节) |
| 数据 | 4000 场半庄 + 1000 场带 10% 随机探索,共 280 万个决策点;验证集 200 场(11 万个);12 进程生成用了 5 分钟 |
| 训练 | 3 轮,7 分钟(RTX 4060 Ti) |
| 验证集同步率 | 95.7%:出牌 94.3%、吃 93.5%、碰 97.8%、过 99.8%、立直和和牌 100% |
| 点炮头 | 真会放铳的牌平均给 10.3%,不会放铳的平均给 1.4% |
| 对 3 个规则型 | 150 个种子 × 4 个座位 = 600 场半庄,平均名次分 −0.34,95% 置信区间 [−2.59, +1.90] → 持平,过关 |

```bash
python -m riichi_ai.generate --games 4000 --workers 12 --out data/rbc/clean
python -m riichi_ai.generate --games 1000 --workers 12 --seed 100000 --explore 0.1 --out data/rbc/explore
python -m riichi_ai.generate --games 200 --workers 12 --seed 200000 --out data/rbc/val
python -m riichi_ai.train_bc --data data/rbc/clean data/rbc/explore --val data/rbc/val --out checkpoints/riichi_bc
python -m riichi_ai.evaluate --candidate checkpoints/riichi_bc/best.pt --baseline shanten -n 150 --workers 12
```

## 5. 自我对弈

| 项 | 设计 |
|---|---|
| 算法 | PPO,不折扣,GAE λ = 0.95 |
| 采样 | 10 进程 × 64 场并排,每轮约 20 万个决定 |
| 对手 | 一半的场四个座位都是当前模型;另一半当前模型坐 1–2 个座位,其余从对手池抽(0 号位固定是模仿模型,其余是训练途中的旧版本) |
| 点炮头 | 自我对弈时继续用看全场算出的标签训练,权重 0.5 |
| 评估 | 每 20 轮对 3 个规则型打 150 个种子 × 4 = 600 场半庄,种子从 1000 万起,和训练不重叠;成绩最好的存 `best.pt` |

```bash
python -m riichi_ai.train_ppo --init checkpoints/riichi_bc/best.pt --out checkpoints/riichi_ppo --minutes 240 --workers 10
python -m riichi_ai.train_ppo --out checkpoints/riichi_ppo --resume --minutes 240      # 接着训
python -m riichi_ai.export --checkpoint checkpoints/riichi_ppo/best.pt --out models/riichi.onnx
```

### 结果(2026-11-22,RTX 4060 Ti)

| 项 | 内容 |
|---|---|
| 训练量 | 295 轮,15.2 万场半庄,3.9 小时(第 100 轮时因为同时跑别的评估内存不足中断过一次,从 latest.pt 接着训,第 100 轮的评估没留下) |
| 最好的一版 | 第 180 轮(9.4 万场半庄,2.5 小时),导出成 `models/riichi.onnx` |
| 之后 | 在 +3 到 +6 之间来回,没有更高;放铳率还在慢慢降(第 280 轮 12.0%) |

定期评估(对 3 个规则型,150 个种子 × 4 = 600 场半庄):

| 轮 | 半庄数 | 平均名次分 | 95% 区间 | 平均顺位 | 和了率 | 放铳率 |
|---|---|---|---|---|---|---|
| 20 | 1.1 万 | +0.82 | [−1.30, +2.93] | 2.472 | 22.6% | 15.6% |
| 60 | 3.2 万 | +3.08 | [+0.38, +5.78] | 2.427 | 22.8% | 13.7% |
| 140 | 7.3 万 | +3.72 | [+0.97, +6.48] | 2.393 | 23.3% | 13.0% |
| **180** | **9.4 万** | **+5.90** | **[+3.25, +8.55]** | **2.322** | **23.8%** | **12.9%** |
| 220 | 11.4 万 | +5.05 | [+2.59, +7.50] | 2.357 | 23.8% | 12.5% |
| 280 | 14.5 万 | +5.19 | [+2.57, +7.80] | 2.358 | 23.4% | 12.0% |

第 180 轮是从 15 次评估里挑出来的最高分,会偏高一点。段位梯用另一批种子(2000 万起,300 个种子 × 4 = 1200 场半庄)重新测过:

| 甲 对 3 个乙 | 简单 | 规则型 | 模仿模型 | 自我对弈 |
|---|---|---|---|---|
| 简单 | — | −36.58 | −35.28 | −39.33 |
| 规则型 | +58.27 | — | +0.44 [−1.01, +1.88] | −5.63 [−7.68, −3.57] |
| 模仿模型 | +58.49 | −0.99 [−2.54, +0.56] | — | −6.38 [−8.29, −4.47] |
| 自我对弈 | +60.73 | **+3.68 [+1.88, +5.47]** | **+5.75 [+3.84, +7.65]** | — |

换了种子之后是 +3.68,比定期评估里的 +5.90 低,但仍然显著强过规则型和模仿模型。和外部最强的开源 AI 比还差得远,见 [riichi-mortal.md](riichi-mortal.md)。

## 6. 入座和提示

| 功能 | 做法 |
|---|---|
| 模型文件 | `models/riichi.onnx`(约 7.7 MB),输出策略、价值、点炮概率三项;看全场的那一路不导出 |
| 推理 | onnxruntime 单线程 CPU,约 1 毫秒一次 |
| 神经网络对手 | 日麻开始页选"神经网络";观战的座位也可以选它 |
| 打牌提示 | 侧栏"提示"开关:模型首选的三个动作和概率、估计这一场还会得多少名次分;手牌上方画每张牌的概率条 |
| 点炮概率 | 点炮头给出 34 种牌各自被荣和的概率;到 8% 的牌在手牌上标"险",选中一张牌时显示它的概率 |
| 复盘分析 | 回放和观战时侧栏显示模型对下一步的看法、实际走法和它的首选是否一样;你自己的牌谱会标出和模型不同的选择 |
| 没有模型时 | 神经网络对手、提示、分析自动停用,其余照常 |

点炮概率是模型对"打出这张、别家能荣和"的估计,标签来自训练时的全场信息,所以它学到的是在只看公开信息时这件事的概率。它不是精确计算,也可能低估少见的形(比如字牌单骑)。
