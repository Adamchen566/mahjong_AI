# 路线图

## 目标

| 编号 | 目标 | 说明 |
|---|---|---|
| 1 | 做出一个可使用的打麻将软件 | 浏览器里 1 人对 3 个电脑,完整流程和结算 |
| 2 | 训练 AI 来打麻将 | 规则型 AI 打底,再用自我对弈强化学习 |
| 3 | AI 加入麻将对局 | 训练出的模型作为可选难度的对手 |

## 已定的范围

| 问题 | 决定 |
|---|---|
| 规则 | 只做四川麻将血战到底 |
| 软件形态 | 本机运行的网页版:Python 本地服务 + 浏览器界面 |
| 联机对战 | **不做**(原阶段 3,搁置) |
| 引擎语言 | Python,对局和训练用同一份引擎 |
| AI 加入对局 | AI 作为玩家坐进软件里的牌局 |
| 暂不做 | 南京麻将、摄像头识别真实牌桌、手机 App |

## 阶段 2:单机可玩的软件

**完成标准**:在浏览器里和 3 个电脑完整打完一局,换三张、定缺、碰杠胡、结算都能操作并显示正确;连打多局有累计分数。

| 步骤 | 内容 | 交付物 |
|---|---|---|
| 2a 本地服务 | FastAPI + WebSocket。服务持有 `Game`,向浏览器发视图和事件,接收动作编号;电脑座位由 `Agent` 自动行动 | `server/` |
| 2b 牌桌界面 | 四家手牌(别人的是牌背)、副露、弃牌区、剩余牌数、缺门标记、当前行动者 | `frontend/` |
| 2c 操作 | 点牌出牌;碰、杠、胡、过按钮;只显示合法的操作 | 同上 |
| 2d 流程界面 | 换三张选牌、定缺选择、胡牌提示、结算页(番型明细 + 每笔分数) | 同上 |
| 2e 多局 | 轮庄、累计积分、再来一局 | 服务端 |
| 2f 牌谱 | 每局自动存牌谱;可以打开一局逐步回放 | `records/` |
| 2g 一键启动 | 一条命令启动服务并打开浏览器 | 脚本 |

| 备注 | 内容 |
|---|---|
| 现有脚手架 | `frontend/` 是 React 19 + Vite 6,目前只有一个调试页 |
| 已知问题 | 牌面图片目录名是 `public/asserts`,代码里写的是 `assets`,做 2b 时统一 |
| 电脑对手 | 先用 `SimpleAgent`,阶段 5 换成训练好的模型 |
| 出牌节奏 | 电脑行动加 0.5–1.5 秒延迟,否则看不清 |
| 依赖 | 开发机已装 fastapi 0.110、uvicorn 0.34、Node 22 |

## 阶段 4:训练 AI

**完成标准**:训练出的模型在至少 1 万局同牌对比中,对规则型 AI 的平均得分显著为正。

方案细节见 [ai-training.md](ai-training.md)。

| 步骤 | 内容 | 过关标准 |
|---|---|---|
| 4a 规则型 AI | 向听数 + 有效进张选牌,加基本的防守和定缺、换牌策略 | 对 `SimpleAgent` 平均得分明显为正 |
| 4b 训练环境 | 状态编码成张量、动作掩码、多进程并行对局 | 编码与视图一致;测出实际对局速度 |
| 4c 模仿学习 | 用 4a 的对局数据训练网络 | 网络与 4a 实力持平 |
| 4d 自我对弈 | PPO,对手池 = 历史版本 + 4a | 对 4a 平均得分显著为正 |
| 4e 评估工具 | 同牌轮换座位对比,报平均分和置信区间 | 新模型过关才替换旧模型 |

| 前置条件 | 现状 |
|---|---|
| 显卡 | RTX 4060 Ti 8 GB,够用 |
| PyTorch | 已装的是 CPU 版(2.7.0+cpu),开始 4c 之前要换成 CUDA 版 |

## 阶段 5:AI 入座

**完成标准**:开局时每个电脑座位可以选难度;训练模型出一手牌的延迟在 1 秒内;有自动化测试证明 AI 拿不到别人的手牌。

| 步骤 | 内容 |
|---|---|
| 5a 模型封装 | 把网络包成 `Agent`,导出 ONNX,用 onnxruntime 在 CPU 上推理 |
| 5b 难度档 | 简单 = `SimpleAgent`,普通 = 规则型 AI,困难 = 训练模型 |
| 5c 公平性测试 | 断言 AI 的输入只来自 `observation(seat)` |
| 5d 提示模式 | 轮到玩家时显示 AI 建议打哪张 |
| 5e 复盘分析 | 回放牌谱时标出 AI 认为的更优选择 |

## 风险

| 风险 | 应对 |
|---|---|
| 规则 bug 污染训练数据 | 引擎测试不过关不开始训练;训练中发现异常牌局用牌谱复现 |
| Python 引擎拖慢训练 | 多进程 → 跳过视图字典直接编码 → 关键函数用 Numba/Rust 重写 |
| 自我对弈不收敛或学不过规则型 AI | 4a 和 4c 各自都是可以直接入座的对手,阶段 5 不被 4d 卡住 |
| 范围膨胀 | 搁置项在阶段 5 完成之前不动 |
